The rule: every hash the graph references must resolve to stored bytes. If it does not, that is a BREAK, written into the ledger and shown on the page.

What broke

6 runs of 001b v6 and 2 runs of 002a v2 trained, but their weights were never stored.

What it costs

Those results stay exploratory. Their numbers are kept, never promoted to evidence.

What changed

Weights hashed every epoch, copied and re-verified, fail-closed check before results are written.

BaeBugs · BioKEA Track A · 8 · custody_break events 96–103 in daisy/impact_mmr.jsonl

Custody here is deterministic: Merkle break points per module, an MMR ledger, LOMO per factor. Variance between runs is fine as long as every step is hashed. The cause of the eight breaks was a kernel bug: the FINISH step exported weights only for runs marked EXECUTED, but EVAL had already relabelled them OBSERVED_EXPLORATORY, so the weights were deleted before export. Their sha256 values are recorded, but no bytes exist, so the resolvability invariant turned each one into an explicit break. Frozen protocols were never edited; fixes went in as amendments.
